# Image-to-3D API generation for the spotlight — design

> Status: approved approach (brainstorm 2026-06-21). Fifth source increment for Subject
> Spotlight, after the point-cloud bridge. First provider: **Tripo**. Feeds the same
> `/spotlight` grid via the generic Generator/ModelOutput schema + the established
> register_output + isolated-scoring pattern.

## Goal

Generate tomato 3D models by feeding **one canonical reference photo** to commercial
image-to-3D APIs, ingesting the results as **AI-reconstruction** entries. This makes the
spotlight's "AI reconstruction" column reflect the real state of the image→3D field for a
whole tomato plant — the benchmark's core question (the tomato Task prompt is literally
"Reconstruct a 3D model from a single RGB image"). Tripo is the first provider; the others
(Meshy/Rodin/Hunyuan) become thin follow-on adapters behind the same interface.

## Why this fits the existing apparatus

- `register_output(db, task_id, generator_slug, data, ext, title, meta, generator_name)`
  (`app/ingest.py:172`) already hashes/dedups/stores the GLB; the caller sets
  `source/license/attribution/external_url` and commits per object — the SAME pattern the
  scan and Objaverse adapters use.
- `Generator` rows for `trellis`/`hunyuan3d`/`instantmesh` are already seeded
  (`app/seed.py:54-58`); a `tripo` generator row is one more `db.add` (idempotent).
- Scoring reuses `recon_service.score_and_store` against the AgriGen scorer (`:8077`),
  isolated/best-effort. AgriGen stays read-only (we only consume its `/score`).
- No schema changes: `meta_json` is a free-form provenance bag; `source` is any string.

## Decisions (locked at brainstorm)

- **One canonical reference image, same for every generator** — an apples-to-apples audit.
- **First provider = Tripo** (`TRIPO_API_KEY`). Pluggable client; others are ~40-line adapters.
- **Reference image is self-sourced** — one open-licensed (CC-BY/CC0) whole tomato-plant photo,
  license vetted and attribution recorded.
- **API recons are AI reconstructions** — `source_class` returns `"ai"` for `api:*` sources so
  they group with local recons, NOT under "Found".
- **Keys from env, never committed/logged.** A provider with no key in env is skipped.
- **Mesh-only output** — APIs return GLB; ingest as-is. (No decimation needed; API meshes are
  already web-scale, unlike the raw laser scans.)

## Components

### 1. Canonical reference image (sourced + wired)

- Source ONE whole-plant _Solanum lycopersicum_ photo under a CC-BY/CC0 license
  (Wikimedia Commons / iNaturalist research-grade). Vet the license against actual use
  (private research tool; attribution recorded), store under
  `data/assets/reference/tomato_ref.jpg`, and record `{source_url, license, attribution}` in a
  small sidecar `data/assets/reference/tomato_ref.json`.
- Wire it as the tomato spotlight's input photo: set the `tomato` entry's `reference_image`
  in `app/spotlight.SPOTLIGHTS` to the served URL (fills the currently-empty reference panel,
  `reference_image: None` today). The generation adapter reads the local file as the API input.
- This is the SINGLE input fed to every provider.

### 2. Provider-agnostic client — `app/image3d.py`

- A provider is a callable `generate(image_bytes: bytes, *, api_key: str, transport=None,
timeout_s: int = 300) -> bytes` that returns GLB bytes, encapsulating the provider's
  submit → poll → download job flow.
- `generate_tripo(image_bytes, *, api_key, transport=None, timeout_s=300) -> bytes`:
  upload/submit the image → receive a task id → poll task status with bounded backoff until
  success or timeout → resolve the model URL → download and return the GLB bytes. Raise
  `Image3DError` on provider error / timeout / empty result. **Exact Tripo endpoints +
  request/response shapes are verified against current Tripo API docs (context7/WebSearch) at
  implementation time — NOT hardcoded from memory.**
- `transport` is an injectable HTTP seam (default: a real httpx client) so unit tests drive
  the submit/poll/download state machine without network.
- `PROVIDERS: dict[str, tuple[callable, str]]` maps slug → (generate fn, env-var name), e.g.
  `{"tripo": (generate_tripo, "TRIPO_API_KEY")}`. Adding Meshy later = one entry + one fn.

### 3. Generation adapter — `scripts/generate_api_recon.py`

- `generate_api_recon(db, image_bytes, *, providers, env, score_fn=None,
task_title=TOMATO_TITLE) -> dict`: resolve the tomato Task by title; for each provider whose
  env key is present:
  - `glb = generate(image_bytes, api_key=key)`
  - `register_output(db, task_id, generator_slug=slug, generator_name=<Name>, data=glb,
ext="glb", title=f"{slug} recon", meta={"depiction":"whole_plant","provider":slug,
"from_reference":"tomato_ref"})`
  - set `out.source = f"api:{slug}"`, `out.license = "<provider> generated-asset terms"`,
    `out.attribution = "Generated by <Name> from CC reference photo"`,
    `out.external_url = <provider result/job URL>`; `db.commit()` (hosted)
  - if `score_fn` and depiction == whole_plant: isolated `score_fn(db, out)` + commit
    (a scoring failure never drops the hosted object).
  - best-effort: one provider's failure logs (no secrets) and the loop continues.
  - Returns `{"generated","errors","by_provider"}`.
- `main()`: load the reference image from `data/assets/reference/tomato_ref.jpg`; build the
  active provider set from `PROVIDERS` filtered to those with a key in `os.environ`; wire
  `recon_service.score_and_store`. If no provider key is set, print a clear key-gated message
  and exit 0 (nothing to do).

### 4. `source_class` extension — `app/sourcing.py`

- `source_class` returns `"ai"` for `source == "bio3d-arena"` OR `source.startswith("api:")`;
  scan sources → `"scan"`; everything else → `"found"`. So API recons render in the spotlight's
  **AI reconstruction** group beside any locally-run recons. (Existing scan/found behavior
  unchanged.)

## Data flow

```
CC tomato photo (data/assets/reference/tomato_ref.jpg)
  └─ generate_api_recon ─► for each provider with a key:
       generate_tripo(image_bytes, api_key) ── submit→poll→download ─► GLB bytes
         └─ register_output(generator_slug="tripo", source="api:tripo", provenance…)
              ├─ score_and_store (isolated; AgriGen :8077; GT band verdict)
              └─ (render_spotlight thumbnail + independent-critic gate — live step)
/spotlight/tomato ─► "AI reconstruction" group (source_class api:* → ai), reference panel shows the input photo
```

## Security & external-data

- API keys read from env (`TRIPO_API_KEY`, …); NEVER committed, echoed, or logged. No
  `bash -x` around key use; redirect any verbose curl/debug to /dev/null. (Key-leak lesson.)
- The only data leaving the machine is the ONE open-licensed public tomato photo — no sensitive
  data. (APIs were the user's explicit choice; flagged for the record.)
- `/spotlight` stays internal-only until the pre-public license re-vet (existing constraint).

## Error handling

- `generate_*` raises `Image3DError` on HTTP error, poll timeout, or empty result; the adapter
  catches it per provider → counts `errors`, logs without secrets, continues.
- Poll uses bounded backoff + hard `timeout_s`; never an unbounded wait.
- Per-object commit; isolated scoring; live run key-gated (no key → no-op with a clear message).

## Testing

- **Unit (mocked transport):** a fake transport returns canned responses through
  submit→poll(running→success)→download, yielding a real GLB (a trimesh box export). Assert
  `generate_tripo` returns those bytes; assert `generate_api_recon` ingests a ModelOutput with
  `source="api:tripo"`, correct provenance, and `source_class("api:tripo") == "ai"`. Assert a
  provider whose key is absent is skipped, and a provider that raises `Image3DError` is counted
  in `errors` without dropping other providers' outputs.
- **Real-execution (key-gated):** one live Tripo generation that **skips cleanly** (never
  fake-passes) when `TRIPO_API_KEY` is unset — proving the real submit/poll/download contract
  only when a key is present (real-execution doctrine, system boundary).
- **Render + independent-critic gate** on the generated GLBs (same discipline as Plant3D):
  my own read is never the terminal gate.

## Out of scope (future increments)

- Additional providers (Meshy/Rodin/Hunyuan) — each a `PROVIDERS` entry + one `generate_*` fn.
- Infinigen procedural generation (separate increment; heavy Blender setup, different category).
- Multi-view / text-prompt generation — the Task is single-image by definition.
- Public licensing re-vet of generated assets (pre-public cleanup, existing deferred task).
