# Comprehensive image-to-3D coverage (aggregators) — design

> Status: approved approach (brainstorm 2026-06-21). Extends the image-to-3D API generation
> increment. Strategy: AGGREGATOR-FIRST (fal.ai + Replicate) + the existing direct Tripo, to
> cover ~12–15 competitive generators with 2–3 keys. Full catalog now.

## Goal

Populate the spotlight's **AI reconstruction** column with as many modern/competitive
image-to-3D generators as possible — so one run per available key audits the whole field for a
tomato. Reuses the existing `generate_api_recon` ingest pipeline; the only new code is two
aggregator transports + a bigger `PROVIDERS` registry.

## Why aggregator-first (verified)

- **[fal.ai/3d-models](https://fal.ai/3d-models)** hosts a uniform-API catalog of image-to-3D
  models (Hunyuan3D v2/v3, TripoSR, Trellis, Hyper3D/Rodin, Tripo v2.5), all GLB out, one
  `FAL_KEY`. **[replicate.com/collections/3d-models](https://replicate.com/collections/3d-models)**
  hosts tencent/hunyuan-3d-3.1, firtoz/trellis, fishwowater/trellis2, hyper3d/rodin, one token.
- One adapter per aggregator (parameterized over a model id) → many generators. ~12–15 entries
  for 2 integrations + 2–3 keys, vs a dozen separate first-party integrations.

## Architecture (extends `app/image3d.py`)

Keep the existing interface `generate(image_bytes, *, api_key, transport=None, timeout_s,
poll_interval_s) -> bytes` and the `PROVIDERS` registry (`slug -> (callable, env_var, name)`).
Add two aggregator generators that take a `model` parameter; bind the model per registry entry
so one env var unlocks many models.

### 1. fal.ai adapter — `generate_fal(image_bytes, *, api_key, model, transport=None, ...)`

- fal queue API (verify exact shapes at impl against fal.ai/docs): submit to the model endpoint
  with the image (base64 data-URI or fal-storage upload) → receive request id + status URL →
  poll until `COMPLETED` → fetch result; the GLB is at `result.model_mesh.url` (field name
  varies by model — verify). Auth header `Authorization: Key <FAL_KEY>`. Raise `Image3DError`
  on error/timeout/empty.
- `FalTransport` = the live binding (httpx). Injectable seam for tests.

### 2. Replicate adapter — `generate_replicate(image_bytes, *, api_key, model, transport=None, ...)`

- Replicate predictions API: `POST /v1/models/{owner}/{name}/predictions` (or `/v1/predictions`
  with a version hash) + `{input: {image: <data-uri-or-url>}}` → poll the prediction GET until
  `status=="succeeded"` → `output` holds the GLB URL → download. Auth `Authorization: Bearer
<REPLICATE_API_TOKEN>`. Raise `Image3DError` on `failed`/timeout/empty.
- `ReplicateTransport` = the live binding. Injectable.

### 3. `PROVIDERS` registry — the full catalog

Each entry binds a model via `functools.partial(generate_fal, model="...")` (or replicate),
sharing the aggregator's env var so all activate with one key:

```
PROVIDERS = {
  "tripo": (generate_tripo, "TRIPO_API_KEY", "Tripo"),                       # existing direct
  # fal.ai (FAL_KEY)
  "fal:hunyuan3d-v2":  (partial(generate_fal, model="fal-ai/hunyuan3d/v2"),          "FAL_KEY", "Hunyuan3D v2 (fal)"),
  "fal:hunyuan3d-v3":  (partial(generate_fal, model="fal-ai/hunyuan3d-v3/image-to-3d"),"FAL_KEY", "Hunyuan3D v3 (fal)"),
  "fal:trellis":       (partial(generate_fal, model="fal-ai/trellis"),               "FAL_KEY", "TRELLIS (fal)"),
  "fal:triposr":       (partial(generate_fal, model="fal-ai/triposr"),               "FAL_KEY", "TripoSR (fal)"),
  "fal:hyper3d":       (partial(generate_fal, model="fal-ai/hyper3d/rodin"),          "FAL_KEY", "Rodin/Hyper3D (fal)"),
  # Replicate (REPLICATE_API_TOKEN)
  "replicate:hunyuan3d-3.1": (partial(generate_replicate, model="tencent/hunyuan-3d-3.1"), "REPLICATE_API_TOKEN", "Hunyuan3D 3.1 (Replicate)"),
  "replicate:trellis":       (partial(generate_replicate, model="firtoz/trellis"),         "REPLICATE_API_TOKEN", "TRELLIS (Replicate)"),
  "replicate:trellis2":      (partial(generate_replicate, model="fishwowater/trellis2"),   "REPLICATE_API_TOKEN", "TRELLIS 2 (Replicate)"),
  "replicate:rodin":         (partial(generate_replicate, model="hyper3d/rodin"),          "REPLICATE_API_TOKEN", "Rodin (Replicate)"),
}
```

Exact model paths / Replicate version hashes / result-field names are **verified at impl** (the
transports are the live bindings — the unit tests pin orchestration via mocked transports). The
binding callable still satisfies the adapter's `fn(image, api_key=key)` call (partial fills
`model`).

### 4. Provenance — provider-aware

`generate_api_recon` currently hardcodes Tripo's `external_url`. Generalize: derive provenance
from the slug prefix — `fal:*` → `https://fal.ai`, `replicate:*` → `https://replicate.com`,
`tripo` → `https://platform.tripo3d.ai`. `license = "<name> generated-asset terms (see provider)"`,
`attribution = "Generated by <name> from CC reference photo"`. Small `_provenance(slug, name)`
helper; everything else in the ingest loop is unchanged.

## Data flow (unchanged from the API increment)

```
tomato_ref.jpg → generate_api_recon → for each PROVIDERS entry whose env var is set:
   generate_fal / generate_replicate (submit→poll→download) → GLB
   → register_output(source="api:<slug>") → source_class "ai" → AI-reconstruction group
   → isolated score → render + critic gate (live step)
```

## Error handling

- Per-provider best-effort (existing): one provider failing never aborts the others; provider
  with no key skipped; scoring isolated. Bounded poll timeout + backoff in each transport.
- Keys NEVER logged (existing discipline); keys only in Authorization headers.

## Testing

- **Unit (mocked transports):** `FakeFalTransport` / `FakeReplicateTransport` drive
  submit→poll(running→done)→download → assert `generate_fal`/`generate_replicate` return the GLB
  and raise on failed/timeout/empty. Assert the `PROVIDERS` registry exposes the expected slugs
  and that all `fal:*` share `FAL_KEY`, all `replicate:*` share `REPLICATE_API_TOKEN`. Assert
  `generate_api_recon` with a fake multi-provider registry ingests each as `source="api:<slug>"`
  and `_provenance` sets the right `external_url`.
- **Real-execution (key-gated):** one live fal call + one live Replicate call that **skip
  cleanly** without the key (proves the real transport contract per aggregator when keyed).
- **Render + independent-critic gate** on the generated models (live step, when keyed).

## Out of scope (future)

- Direct first-party APIs for marquee providers (Meshy/Rodin direct) — only if the
  aggregator-hosted version proves insufficient.
- A leaderboard/per-generator aggregation UI for the now-larger AI-recon column (the grid already
  lists them; ranking is a separate increment).
- Cost controls / batching across many models (each generation costs ~$0.05–0.30).
